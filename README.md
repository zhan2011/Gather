# 报名 / 问卷 / 投票 系统

一个**零依赖**（只用 Python 标准库）的小网站，同一个服务同时管三类活动：

| 类型 | 用来做什么 | 典型场景 |
| --- | --- | --- |
| **报名** | 选项目 + 填学号姓名，可选名额上限 | 活动分时段报名、班服尺码统计、值日分组 |
| **问卷** | 单选 / 多选 / 填空，选项题还能追加「其他」自填 | 课程反馈、需求调查、意见收集 |
| **投票** | 单选或多选，可实时公开结果 | 选班服、定活动时间、评优 |

学生用手机打开首页就能直接报名 / 答卷 / 投票；管理员在后台发起活动、看实时统计、导出 Excel。
可配合 mefrp（幻缘映射）等内网穿透分享给同学。

---

## 一分钟启动

1. 电脑装好 Python 3.8+（Windows 安装时勾选 *Add python.exe to PATH*）。
2. 双击 `start.bat`（也可以在命令行里跑 `python app.py`）。
3. 终端会打印三个地址，浏览器打开**本机地址** `http://127.0.0.1:8000` 就能看到首页。
4. 管理员入口：`http://127.0.0.1:8000/admin`。

> 默认管理员账号 `admin`，密码：123456。

## 使用流程

### 学生端（手机 / 电脑都一样）

1. 打开首页，看到所有进行中的活动（可按 报名 / 问卷 / 投票 筛选）；
2. 点「去填写」，填完提交；
3. 报名和投票提交后能看到实时结果；问卷是否显示结果由管理员决定；
4. 活动到期或管理员结束后，按钮变成「查看结果」，只能看不能再交。

> 首页最上方是**公告**，管理员发布后这里就会显示，置顶的排在最前面；公告多于 2 条时可以点「查看其余 N 条」展开。

> 首页右上角可以「登录 / 注册」一个普通账号（用户名 2-20 位、密码至少 6 位）。
> 登录后提交会记在账号名下，**次数按账号算**，换手机、换网络都不会多算；
> 不登录也能填，**次数按 IP 算**。管理员提交不计次。
> 如果管理员把某个活动的「允许未登录的访客填写」关掉，就必须先登录才能提交。
>
> **注册限制**：同一个网络（IP）每周最多自助注册 1 个账号，防止一个人刷一堆号。
> 如果班里很多同学共用同一个 Wi-Fi，请让管理员在后台「普通成员 → 新增成员」批量代建，代建不受这条限制。
>
> **拿不到真实 IP 的时候**：如果用 TCP 模式的内网穿透把服务开到公网，穿透只转发端口、不会带上访客的地址，
> 服务端看到的永远是 `127.0.0.1`。这时系统会自动改用浏览器里的一个标识（`device_id` cookie）来区分访客，
> 也就是说「每 IP 1 次」「每周注册 1 个」会变成「每台设备 1 次」。
> 想让限制严格按真实 IP，两个办法：换带 `X-Forwarded-For` 的 HTTP/HTTPS 隧道，
> 或者在内网穿透的「高级配置」里打开 **PROXY protocol**（本项目已支持 v1 / v2 两种格式，推荐 v1——
> 它是可读的一行 ASCII，出问题在日志里能直接看出原样）。
> 登录后点顶栏「我的账号」可以改名字、改密码（改密码要输原来的密码）。

> 选择题如果管理员勾了「允许填其他」，选项里会多一个「其他」，选中后可以在下面自己写一段话；
> 在输入框里打字时会自动帮你把「其他」勾上，不用手动点。统计时这些内容会汇总成一条「其他」，展开能看到每段原文。
>
> 多选题如果设了「最多选几项」，勾满之后其余选项会变灰点不动，取消一个再放开；题干右边会实时显示「已选几项」。

### 管理员端

1. 首页右上角「管理员入口」→ 输入用户名密码登录；
2. 「＋ 发起报名 / ＋ 发起问卷 / ＋ 发起投票」创建活动；
3. 每个活动可以设置：
   - **截止时间**：到点自动停止收表（留空=不限）；
   - **最多提交几次**：0 = 不限；登录的账号按账号计次，未登录的访客按 IP 计次；管理员不计次；
   - **是否允许未登录的访客填写**：关掉后必须登录普通账号才能提交；
   - 报名：项目列表（名称 / 图标 / 名额，名额 0 = 不限）、是否允许同一人报多个项目；
   - 问卷 / 投票：题目（题干、单选 / 多选 / 填空、选项、是否必答、选项题是否允许填「其他」、多选题最多选几项）、是否实时公开结果；
4. 「查看明细」看统计图和逐条记录，可删除某一条、导出 **Excel / CSV**；
5. 管理员也可以直接点「去参与」以自己身份填写，**不占用本 IP 的次数**；
6. 「普通成员」页可以看所有注册的参与者账号（用户名、昵称、提交次数、注册时间、最近登录），
   支持按名字搜索、**新增成员**（代建，不受每 IP 每周 1 个的限制）、**重置密码**、**删除账号**；
   删除后他自己提交的记录会保留，记录里还是当时的昵称。
7. 「公告」页发布通知：填标题和内容（内容可以分多行），可以勾「置顶」排到首页最前面；
   已发布的公告能编辑、能「暂时隐藏」（隐藏后首页不显示，但不会删掉）、也能直接删除。
8. 「封禁名单」页管来源：在活动明细里对某一条记录点 **拉黑**，就封住它背后的
   IP 或设备标识——被封的来源**不能再提交、也不能再注册新账号**（管理员账号不受影响）。
   封禁时可以顺手写个原因，事后在这里点「解除」恢复。

## 需求对照表

| 要求 | 实现 |
| --- | --- |
| 首页 UI 报名 / 问卷 / 投票 | 首页活动列表 + 分类筛选，点卡片进入填写页 |
| 适用手机端 | 响应式布局，移动端单列大按钮，`viewport-fit=cover` 适配刘海屏 |
| 管理员入口登录后发起活动 | `/admin` → 登录 → 「＋ 发起…」 |
| 管理员也能参与 | 登录状态下打开活动页直接填，不计次也不计名额限制之外的东西 |
| 支持多个管理员账户 | 「管理员账号」页新增 / 改密码 / 删除；分高级与普通两级 |
| 有截止日期 | 每个活动独立设置，到期自动变「已截止」并拒绝提交 |
| 限制每个 IP 填报次数 | 每个活动独立计数，默认 1 次；未登录按 IP、登录按账号；管理员豁免；手动结束与截止后同样拦截 |
| 普通账号注册登录 | 首页「登录 / 注册」，用户名 2-20 位、密码 ≥6 位；同一 IP 每周限注册 1 个，管理员可代建 |
| 自己改资料 | 登录后点「我的账号」，可改名字（2-20 字）和密码（需验旧密码） |
| 公告 | 后台「公告」页发布 / 编辑 / 隐藏 / 删除，首页顶部展示，支持置顶 |
| 封禁来源 | 明细里点「拉黑」即封住该 IP / 设备；被封来源不能提交也不能注册，可随时解除 |

### 普通账号 vs 访客

| | 访客（未登录） | 普通账号 | 管理员 |
| --- | --- | --- | --- |
| 能填写 | 活动允许时 | 是 | 是 |
| 次数怎么算 | 按 IP | 按账号 | 不计次 |
| 明细里显示 | 访客 | 昵称 | 管理员 + 用户名 |

> 在后台「发起 / 编辑活动」里可以关掉「允许未登录的访客填写」，那样就只有登录后的账号能提交。

### 两级管理员权限

| 操作 | 高级管理员 | 普通管理员 |
| --- | --- | --- |
| 发起 / 设置 / 结束 / 删除活动 | 是 | 是 |
| 查看明细、导出、删除单条记录 | 是 | 是 |
| 修改自己的密码 | 是 | 是 |
| 新增 / 删除管理员、改他人密码 | 是 | 否 |

> 系统始终至少保留一个管理员；唯一的「高级管理员」不能删除。

## 文件结构

```
sports-signup/
├─ start.bat           双击启动（Windows）
├─ app.py              HTTP 服务与全部接口路由
├─ store.py            数据层：活动、问卷题目、提交记录、账号、公告、封禁名单
├─ settings.py         路径与 config.json 读写
├─ exporters.py        Excel（xlsx）/ CSV 导出，纯标准库手写
├─ config.json         站点标题、端口、初始管理员密码
├─ data/signup.db      SQLite 数据库（活动 / 提交 / 账号 / 公告 / 封禁都在这）
├─ data/signup.db.bak  改造前的旧数据库备份
└─ static/             前端：index / activity / admin 三个页面
```

`config.json` 说明：

```json
{
  "port": 8000,
  "admin_password": "zhan",
  "title": "班级活动中心",
  "subtitle": "点开下面的活动，报名、填问卷或投票"
}
```

- `port`：监听端口，被占用时自动往后顺延；
- `admin_password`：**仅在数据库里还没有任何管理员时**用来创建 `admin` 账号，之后改密码请在后台操作；
- `title` / `subtitle`：首页标题与副标题。

## 内网穿透：mefrp（幻缘映射）怎么配

ME Frp 的隧道类型有三种，官方 Web 穿透指南里的对照表如下
（来源：[ME Frp · Web 应用穿透指南](https://www.mefrp.com/docs/app/website)）：

| 隧道类型 | 支持的协议 | 是否必须带端口访问 | 绑定自己的域名 | 访问形式 |
| --- | --- | --- | --- | --- |
| **TCP** | HTTP / HTTPS | 是 | 可选 | `http://节点域名:远程端口` |
| HTTP | HTTP | 否 | 必须 | `http://site.example.com` |
| HTTPS | HTTPS | 否 | 必须 | `https://site.example.com` |

### 推荐：先用 **TCP 隧道**（不需要域名、不需要备案，5 分钟就能分享）

1. 先双击 `start.bat` 把网站跑起来，确认本机 `http://127.0.0.1:8000` 能打开；
2. 登录 mefrp 控制台 →「创建隧道」→ 选择带 **TCP** 标识的节点；
3. 填写：
   - 本地地址：`127.0.0.1`
   - 本地端口：`8000`（以 `start.bat` 窗口里显示的实际端口为准）
   - 远程端口：用「获取随机空闲端口」自动分配
4. 创建成功后，**访问地址就是 `http://节点域名:远程端口`**，把它发到班级群即可；
5. TCP 隧道**不需要做域名解析**。

> 注意：链接带端口号，部分手机浏览器/微信里点击可能提示「非官方网页」，确认继续即可。

### 有备案域名时：用 **HTTPS 隧道**（最整洁，链接不带端口）

1. 创建隧道时选带 **HTTP(S)** 标识的节点，可用控制台右上角的「可建站」筛选；
2. 本地地址 `127.0.0.1`、本地端口 `8000`，**域名**填你要绑定的域名；
3. 在控制台「隧道管理 → 更多 → 查看详情」里找到**域名解析配置**，到域名服务商处加一条
   `A 记录` 或 `CNAME 记录` 指向它提示的解析目标，等 DNS 生效（几分钟到几小时）；
4. 访问 `https://你的域名` 即可，学生输入网址最省事。

### 选节点与合规要点（官方文档提醒）

- 用 **HTTP(S) 隧道 + 中国大陆节点** 时，**必须使用已备案的域名**；
- 部分节点对建站功能有特殊限制，选节点时注意看备注，用「可建站」筛选更稳；
- 只用 TCP 隧道、绑定自己域名是「可选」的，所以没有域名时走 TCP 最省事。

### 用 Cloudflare 代理时

若域名走 Cloudflare：隧道是 HTTP 类型时，SSL/TLS 模式要选 **「关闭」或「灵活」**；
选了「完全 / 完全(严格)」会导致流量到不了隧道、只显示幻缘映射默认页
（见官方文档同一页）。

## 安全与注意事项

- **先把默认密码改掉**，尤其是公网穿透出去以后（后台 →「管理员账号」→ 改密码）；
- 管理端用 Cookie 会话（HttpOnly、SameSite=Lax），每次请求都会回库校验账号是否还存在；
- 建议给同学用 **HTTPS 隧道**：TCP/HTTP 都是明文，管理密码和学号姓名不加密传输；
- IP 次数统计依赖请求来源地址；走内网穿透时，只有当请求来自本机 / 内网时才会采信
  `X-Forwarded-For` / `X-Real-IP` / `PROXY protocol`，避免公网直接伪造 IP 绕过限制；
- 如果穿透（尤其是 TCP 隧道）根本没带来源地址，服务端只会看到 `127.0.0.1`，此时会自动退回按浏览器标识
  （`device_id` cookie）区分访客，明细里显示为「同一设备」。清掉浏览器 cookie 就能重置这个标识；
- **PROXY protocol**：内网穿透的「高级配置」里打开后，穿透会在每条连接开头先说真实来源。本项目会自动识别
  v1（`PROXY TCP4 1.2.3.4 ...` 一行 ASCII）和 v2（12 字节签名 + 二进制地址块），把真实 IP 用于限次、注册限制、
  封禁名单和明细。注意顺序：**先重启本服务，再去面板开开关**，否则开关先打开时第一条请求会被当成非法请求行。
- 学号、姓名属于个人信息，只用于本次统计，活动结束及时停止服务并妥善处理 `data/signup.db`；
- 服务监听本机全部网卡的选定端口，跑在公网前请确认防火墙 / 端口开放情况；
- **登录有失败次数限制**：同一个来源 15 分钟内失败 10 次就锁 15 分钟（返回 429，带 `Retry-After`），
  普通账号和管理员入口各算各的；登录成功的瞬间清零。锁定期间即使密码正确也进不去，等一会儿再试；
- 登录失败一律回同一句「账号或密码错误」，不管账号存不存在、是不是管理员，避免被拿来枚举用户名；
  只有密码校验通过之后，才会提示「这是管理员账号，请到管理员入口登录」——那时对方本来就知道这组凭证；
- 账号不存在和密码错误在**耗时**上也做成一样（都跑一遍同样轮数的哈希），防止用响应时间猜账号。
- 清掉浏览器 cookie 可以换一个「来源」，所以上面的限流挡的是同一个浏览器反复撞；
  真要防住有心的攻击者，最有效的还是**用长密码**。

## 数据与备份

- 所有数据都在 `data/signup.db`；升级前已把旧库备份成 `data/signup.db.bak`；
- 首次用新版本启动时，旧的 `signups` 表会自动迁移成一条「体育选修课报名」活动，历史记录不会丢；
- 建议每次活动结束在后台导出一份 Excel 留档。

## 常见问题

**Q：双击 start.bat 提示找不到 Python？**
装 Python 3.8+ 并勾选 *Add python.exe to PATH*，重开命令行窗口再试。

**Q：终端里端口是 8001 而不是 8000？**
8000 被占用了，程序自动顺延。mefrp 里的「本地端口」改成终端显示的实际端口即可。

**Q：想换一台电脑继续用？**
把整个 `sports-signup` 文件夹拷过去（含 `data/signup.db`），双击 `start.bat` 即可。

**Q：数据会丢吗？**
每次提交立即写库；建议活动结束前在管理端导出一份 Excel 备份。

**Q：同一个同学报错了想改怎么办？**
管理员在「查看明细」里删掉那条记录，对方就能重新提交（若 IP 次数已用完，需要调大次数或让管理员代填）。

**Q：活动发错了，能改题目吗？**
题干 / 项目名称发布后不可改（避免与已有提交对不上），但**名额、截止时间、每 IP 次数、标题和说明随时可以在后台「编辑」里改**。
名额调小时不能低于已报人数；填 0 表示不限。要换题就新建一个活动，再把旧的结束掉。

**Q：有人刷票，怎么封？**
在活动「查看明细」里找到那条记录，点「拉黑」。之后这个来源（设备标识 `dev-…` 或真实 IP）
就不能再提交、也不能再注册新账号，管理员账号不受影响。封错了去「封禁名单」页点「解除」。
注意两点：封 **IP** 可能连带同一 Wi-Fi 下的其他同学；封 **设备** 的话，对方清掉浏览器 cookie 就能绕开，
适合挡住随手刷票的人，不适合对付有心的人。
